# PDF翻訳デスクトップアプリ (PDF to Markdown Translator) 開発仕様書

## 1. 概要
本アプリケーションは、Windows 11環境で動作するデスクトップ向けPDF翻訳ツールです。主に英語の学術論文PDFを対象とし、最新の大規模言語モデル（LLM）のVision機能（画像入力機能）を用いて、1ページずつレイアウトを維持したまま高精度に日本語へ翻訳し、Markdown（.md）形式で出力します。

## 2. 動作環境・制約
*   **対象OS:** Windows 11 (64-bit)
*   **プログラミング言語:** Python 3.12
*   **パッケージ管理:** `uv`
*   **利用者想定:** 個人利用のみ（ただし、環境構築不要で利用できるインストーラー形式で配布可能とする）

## 3. 技術スタック
*   **GUIフレームワーク:** `CustomTkinter` (Windows 11のモダンなUIに合わせやすく、実装が容易なため) または `PySide6`
*   **PDF処理・画像化:** `PyMuPDF` (PDFからのページ画像抽出が高速かつ単体で動作するため)
*   **LLM APIクライアント:**
    *   Google: `google-generativeai` (Gemini API用)
    *   OpenAI: `openai` (GPT API用)
*   **設定管理・セキュアストレージ:**
    *   基本設定: `json` (前回開いたフォルダ、言語設定、選択したLLMを保存)
    *   APIキー保存: `keyring` (OS標準の資格情報マネージャーに暗号化して安全に保存)
*   **パッケージング・インストーラー作成:** `PyInstaller` (単一実行ファイル化) + `Inno Setup` または `NSIS` (インストーラー作成)

## 4. 機能要件

### 4.1. 翻訳処理と出力
*   **入力:** ユーザーが選択したPDFファイル（英語の学術論文を想定）
*   **処理:** PDFを1ページごとに画像としてレンダリングし、選択されたLLMのVision対応APIへ送信。
*   **APIプロンプト（要件）:** 「提供された画像（学術論文のページ）の内容を読み取り、指定された翻訳先の言語（例：日本語）に翻訳してください。出力はMarkdown形式とし、見出し、段落、箇条書き、数式、表などの論理構造を可能な限り維持してください。」
    *   **2ページ目以降の処理:** 文脈を維持するため、前のページの翻訳結果の末尾部分（数文〜段落程度）をシステムプロンプトに含め、「前のページからの続きです。以下の文脈を考慮して翻訳してください：[前のページ末尾のテキスト]」のように指示を追加する。
*   **出力:** 元のPDFファイルと同じディレクトリに、拡張子を `.pdf` から `.md` に変更したファイルを作成。1ページ翻訳完了するごとにファイルに追記（Append）して保存する。

### 4.2. ユーザーインターフェース (GUI)
以下の要素を配置する。
1.  **PDFファイル選択:** パソコン内のPDFファイルを参照して選択するボタンとパス表示欄。
2.  **言語選択:**
    *   翻訳元 (Source): 英語 (デフォルト) / 日本語
    *   翻訳先 (Target): 日本語 (デフォルト) / 英語
3.  **ページ範囲指定:** 開始ページと終了ページを入力（デフォルトは最初から最後まで）。
4.  **LLMモデル選択:**
    *   例: `Gemini 3 Flash` 、`GPT-5 mini` 等のプルダウン。
5.  **APIキー入力:** 選択したモデルに対応するAPIキーの入力フィールド（パスワードのように `*` または `●` でマスク表示する）。
6.  **実行ボタン:** 翻訳処理を開始する。
7.  **進捗表示:** 現在の処理ページ数やステータスを表示するプログレスバーとテキスト（GUIがフリーズしないよう別スレッドで処理を行う）。

### 4.3. 設定の永続化
前回の入力を保存し、次回起動時に復元する。
*   **保存対象:** 前回開いたフォルダパス、翻訳元の言語、翻訳先の言語、選択されたLLMモデル、APIキー。
*   APIキーはOSのセキュアな領域に保存し、平文のファイルには書き出さない。

## 5. 実装ステップ（AIコーディングエージェント向け）

本プロジェクトは以下のステップに沿って1つ1つ順番に実装を進めてください。

### Step 1: プロジェクトの初期化と環境構築
*   `uv init` を実行してプロジェクトを初期化する。
*   必要なパッケージ (`customtkinter`, `PyMuPDF`, `openai`, `google-generativeai`, `keyring`, `pyinstaller` 等) を `uv add` でインストールする。
*   ソースコード用のディレクトリ（例: `src`）を作成する。

### Step 2: PDF画像抽出モジュールの実装 (`src/pdf_processor.py`)
*   `PyMuPDF` を使用し、指定されたPDFファイルのパスとページ範囲を受け取る。
*   各ページを高解像度の画像（PNGまたはJPEG）としてメモリ上（または一時ファイル）に出力するジェネレーター関数を実装する。

### Step 3: LLM翻訳モジュールの実装 (`src/translator.py`)
*   画像データと設定（モデル名、言語、APIキー）を受け取るインターフェースを作成。
*   OpenAI API (GPT Vision) および Google GenAI API (Gemini Vision) を呼び出し、画像をMarkdown形式のテキストに翻訳・変換する処理を実装。
*   エラーハンドリング（レートリミット、APIキーエラー等）を実装する。

### Step 4: 設定・状態管理モジュールの実装 (`src/config_manager.py`)
*   `json` と `keyring` を組み合わせて、設定ファイル（例: `~/.pdf_translator/config.json` または `%APPDATA%` 内）への読み書きを行うクラスを実装。
*   APIキーの安全な保存・取得メソッドを実装。

### Step 5: GUIの構築 (`src/app.py`)
*   `CustomTkinter` を用いて、要件定義にあるUI要素をレイアウトする。
*   UI部品と Step 4 の設定管理を紐づけ、起動時に前回の設定を読み込む。
*   APIキーの入力欄は `show="*"` を設定してマスキングする。

### Step 6: 統合とマルチスレッド処理の実装
*   UIの「実行」ボタンが押された際のフローを構築する。
*   重い処理（PDF画像化、API通信）でUIがフリーズしないよう、`threading` モジュールまたは `concurrent.futures` を使用してワーカースレッドで処理を実行する。
*   ワーカースレッドからメインスレッドのプログレスバーやステータス表示を更新する仕組みを実装。
*   1ページごとに指定された `.md` ファイルへ追記（Append）する処理を実装。

### Step 7: パッケージングとインストーラーの作成 (`scripts/build.py`)
*   `PyInstaller` の設定ファイル (`.spec`) を作成し、単一の `.exe` ファイルとしてビルドするコマンドを用意する。
*   インストーラーを作成するための `Inno Setup` スクリプト (`.iss`) を自動生成、または手動で定義し、コンパイルしてインストーラー (`.exe`) を生成するフローを確立する。
