# PDF翻訳デスクトップアプリ (PDF to Markdown Translator) 開発仕様書

## 1. 概要
本アプリケーションは、Windows 11環境で動作するデスクトップ向けPDF翻訳ツールです。主に英語の学術論文PDFを対象とし、大規模言語モデル（LLM）を用いて、1ページずつレイアウトを維持したまま日本語へ翻訳し、Markdown（.md）形式で出力します。

## 2. 動作環境・制約
*   **対象OS:** Windows 11 (64-bit)
*   **プログラミング言語:** Python 3.14
*   **パッケージ管理:** `uv`。ソースコードは `src` フォルダ、テストコードは `tests` フォルダに置く。`pytest` を使用して単体テストする。
*   **利用者想定:** 個人利用のみ（ただし、環境構築不要で利用できるインストーラー形式で配布可能とする）

## 3. 技術スタック
*   **GUIフレームワーク:** `CustomTkinter` (Windows 11のモダンなUIに合わせやすく、実装が容易なため)
*   **PDF処理:** `PyMuPDF` (PDFからのページ抽出が高速かつ単体で動作するため)
*   **LLM APIクライアント:**
    *   Google: `google-genai` (Gemini API用)
    *   OpenAI: `openai` (GPT API用)
*   **設定管理・セキュアストレージ:**
    *   基本設定: `json` (前回開いたフォルダ、言語設定、選択したLLMを保存)
    *   APIキー保存: `keyring` (OS標準の資格情報マネージャーに暗号化して安全に保存)
*   **パッケージング・インストーラー作成:** `PyInstaller` (単一実行ファイル化) + `Inno Setup` (インストーラー作成)

## 4. 機能要件

### 4.1. 翻訳処理と出力
*   **入力:** ユーザーが選択したPDFファイル（英語の学術論文を想定）
*   **処理:** PDFを1ページごとに切り抜いて、選択されたLLMのAPIへ送信。
*   **APIプロンプト（要件）:** 「提供されたPDFページの内容を読み取り、指定された翻訳先の言語（例：日本語）に翻訳してください。出力はMarkdown形式とし、見出し、段落、箇条書き、数式、表などの論理構造を可能な限り維持してください。応答には翻訳結果だけを含めてください。」
    *   **2ページ目以降の処理:** 文脈を維持するため、前のページの翻訳結果の末尾部分（数文〜段落程度）をシステムプロンプトに含め、「前のページからの続きです。以下の文脈を考慮して翻訳してください：[前のページ末尾のテキスト]」のように指示を追加する。
*   **出力:** 元のPDFファイルと同じディレクトリに、拡張子を `.pdf` から `.md` に変更したファイルを作成。1ページ翻訳完了するごとにファイルに追記して保存する。

### 4.2. ユーザーインターフェース (GUI)
以下の要素を配置する。
1.  **PDFファイル選択:** パソコン内のPDFファイルを参照して選択するボタンとパス表示欄。
2.  **言語選択:**
    *   翻訳先 (Target): 日本語 (デフォルト) / 英語
3.  **ページ範囲指定:** 開始ページと終了ページを入力（デフォルトは最初から最後まで）。
4.  **LLMモデル選択:**
    *   例: `Gemini 3 Flash Preview` 、`GPT-5.4 mini` 等のプルダウン。
5.  **APIキー入力:** 選択したモデルに対応するAPIキーの入力フィールド（パスワードのように `*` または `●` でマスク表示する）。
6.  **実行ボタン:** 翻訳処理を開始する。翻訳中は中断ボタンに変えて、翻訳を中断できるようにする。
7.  **進捗表示:** 現在の処理ページ数やステータスを表示するプログレスバーとテキスト（GUIがフリーズしないよう別スレッドで処理を行う）。

### 4.3. 設定の永続化
前回の入力を保存し、次回起動時に復元する。
*   **保存対象:** 前回開いたフォルダパス、翻訳先の言語、選択されたLLMモデル、APIキー。
*   APIキーはOSのセキュアな領域に保存し、平文のファイルには書き出さない。
